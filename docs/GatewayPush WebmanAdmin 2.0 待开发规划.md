# GatewayPush WebmanAdmin 2.0 待开发规划

> 生成时间：2026-09-24 · 来源：P0~P5 全部落地后的能力缺口盘点
> 定位：**规划文档，非排期承诺**。每项标注侵入性（是否需要改主项目）与建议优先级。
> 前置阅读：`docs/GatewayPush WebmanAdmin 管理后台详细设计.md`（§7 路线图 P0~P5 均已完成）。

## 0. 现状基线（2.0 起点）

后台已具备：会话查询 / 推送管理（含模板、历史、离线队列）/ 动作调试 / 运维操作
（kick / revoke / unbind / force-offline / purge-offline）/ 审计 / RBAC（只读、运维两角色）
/ 运维页 `/ops`（日志尾读、角色三源探测、密钥轮换引导、Redis 键巡检、API 探活）。

**刻意不做（2.0 仍维持）**：

- **Token 生成器** —— `AUTH_SECRET` 不在后台信任域内（设计文档 §3.4 / A1~A5 信任域决策：
  只有 `API_SECRET` 兼任管理面凭证）。做它需重新评估信任边界，或由主项目新增
  `token:issue` 运维动作，**除非用户明确拍板，否则不立项**。
- docblock 精确 shape（主项目侧，与后台无关，维持缓做）。

## 1. 监测方向

### 1.1 指标趋势采样页 ★ 建议首做

| 维度 | 说明 |
|---|---|
| 现状 | 主项目 `/metrics.json` 只有**当前快照**（gauge/counter/task/meta），独立 dashboard 面板（8291）无历史曲线 |
| 做法 | admin 侧定时任务（如 30s/60s）拉 `/metrics.json` 采样落库（admin 自有表），前端画趋势曲线 |
| 侵入性 | **纯 admin** |
| 收益 | 在线数 / 消息量 / 队列深度的时序视角；独立 dashboard 面板可退役，监控入口收敛到后台 |
| 注意 | 采样任务失败要静默降级不刷错误日志；表要按天分区或定期归档（参照 `LOG_KEEP_DAYS` 的做法） |

### 1.2 队列深度巡检

| 维度 | 说明 |
|---|---|
| 现状 | 各队列深度散在 metrics gauge 里，无集中视图 |
| 做法 | 运维页加「队列」区块：`queue:udp:in/out`、`push:offline` 总量、`action:result` 积压数，超阈值标红 |
| 侵入性 | 纯 admin |
| 阈值 | 起步值建议：UDP 队列 > 1000、action 积压 > 100；上线后按实际水位调 |

### 1.3 限流命中统计

| 维度 | 说明 |
|---|---|
| 现状 | `rate:*` 键只在主项目内部使用，被限流的客户端「静默收不到回执」，排查全靠翻日志 |
| 做法 | 只读展示当前正在命中限流的 IP / 命中次数（读 Redis 键即可） |
| 侵入性 | 纯 admin |

### 1.4 错误日志聚合

| 维度 | 说明 |
|---|---|
| 现状 | `error_{date}.log`（error 级双写）已有，但只有 P5 尾读（人工看） |
| 做法 | 按角色聚合今日 error 条数 + 最新 N 条原文；关键字过滤复用 `LogTailService` |
| 侵入性 | 纯 admin |

### 1.5 告警推送

| 维度 | 说明 |
|---|---|
| 现状 | 无任何主动告警，故障全靠人发现 |
| 做法 | 基于 §1.1 采样数据的阈值告警（队列积压 / 角色失联 / 错误激增）→ 邮件或 webhook；admin 定时任务实现 |
| 侵入性 | 纯 admin |
| 依赖 | 建议在 §1.1 之后做（复用采样数据）；告警去重 / 静默窗口是必做细节，防止风暴 |

## 2. 运维方向

### 2.1 配置查看（脱敏）

| 维度 | 说明 |
|---|---|
| 现状 | 只有密钥轮换引导；主项目配置漂移（改了 .env 忘重启等）排查靠登录机器 |
| 做法 | 只读展示主项目关键配置（端口 / 开关 / 阈值），脱敏复用 `SecretMasker` |
| 侵入性 | 纯 admin（读主项目 `.env` + `config/`，路径穿越防护参照 `LogTailService` 三关） |
| 价值 | 「配置漂移」是本项目高频误判源（无热重载 + `.env` 只对新进程生效） |

### 2.2 主项目版本 / 环境页

| 维度 | 说明 |
|---|---|
| 现状 | roles 探测里有部分信息（PID / 启动时间 / tasks） |
| 做法 | 补 PHP 版本 / workerman 版本 / `APP_ENV` / composer 包版本，与 roles 页合并即可 |
| 侵入性 | 纯 admin |

### 2.3 撤销名单管理增强

| 维度 | 说明 |
|---|---|
| 现状 | 撤销名单只读列表已有；revoke 错误操作只能等 TTL 自然过期 |
| 做法 | 主项目新增「解除撤销」运维动作（channels=http + 审计），后台加按钮 |
| 侵入性 | **主项目 1 个动作**（全套配套：config 声明 + 后台端点/节点/测试 + e2e [Q] 扩动作，见 D37 清单） |
| 优先级 | 中 —— 属「给错误操作留后悔药」，价值取决于 revoke 使用频率 |

### 2.4 手动触发 log-cleanup

| 维度 | 说明 |
|---|---|
| 现状 | `log-cleanup` 定时任务已声明 `run_at_start`，但无手动入口 |
| 做法 | 复用动作通道新增运维动作；权限节点单独控（不给只读） |
| 侵入性 | **主项目 1 个动作** |
| 优先级 | 低 —— 磁盘紧张时才有用 |

## 3. 使用方向（业务）

### 3.1 主题广播页 ★ 使用方向首做

| 维度 | 说明 |
|---|---|
| 现状 | `Push::enqueueTopic()` 是广播唯一入口，**无 HTTP 通道**，后台完全够不着；发广播只能写脚本 |
| 做法 | 主项目新增 `broadcast` 运维动作（`channels => [http]`、仅限管理面），后台加广播页（主题 / 内容 / 确认） |
| 侵入性 | **主项目 1 个动作** + 后台完整配套 |
| 红线 | 新增运维动作**必须**走 D37 四处同步清单（config 声明 + 后台四件套 + 两份契约测试 + e2e [Q]），且补 `channels => [http]` 反向白名单（红线 ㊸） |
| 价值 | 补齐「三条通道里后台够不着的最后一条」，运维可从页面发系统公告 |

### 3.2 uid 一站式排查页

| 维度 | 说明 |
|---|---|
| 现状 | 会话 / 绑定设备 / 离线队列 / 撤销名单**分散在四个查询入口** |
| 做法 | 输入一个 uid，聚合展示全部状态（纯前端并行调既有 4 个端点） |
| 侵入性 | 纯 admin（半天量级） |

### 3.3 推送送达率统计

| 维度 | 说明 |
|---|---|
| 现状 | push history 只有「已受理」；实际下发数在 metrics counter 里，两者没对上过 |
| 做法 | 结合 §1.1 采样：受理数 vs 实际下发数做比值趋势（口径差异要标注清楚，避免误读） |
| 侵入性 | 纯 admin |
| 依赖 | §1.1 |
