# Workerman 框架 AI 编码规范（适配 Cursor/Claude Code/CodeBuddy）

**适用说明**：Workerman 无官方完整编码规范，本文档整合 **Workerman 底层运行机制强制约束 \+ PHP PSR\-12 标准 \+ 常驻内存/多进程避坑最佳实践**，可直接作为 AI 编程固定 System Prompt，杜绝 AI 生成坑代码、内存泄漏、进程崩溃、事件阻塞等问题。

**覆盖场景**：原生 Workerman、Webman 框架、Workerman 协程项目、TCP/UDP/WebSocket 长连接服务

## 一、核心强制原则（AI 最高优先级执行）

所有代码生成、改写、重构必须优先遵守以下底层模型规则，优先级高于普通代码风格。

1. **主/子进程资源隔离（致命红线）**

    - `Worker::runAll()` 之前为主进程，**禁止初始化任何网络连接**（MySQL、Redis、MQ、HTTP 客户端等）

    - 所有网络资源、连接实例，必须在 `onWorkerStart` 回调内初始化

    - 禁止多进程共享 Socket 连接，避免数据错乱、断线重连失败

2. **常驻内存状态隔离**

    - 进程启动后内存常驻，全局变量、静态变量不会自动清空

    - **严禁用全局/静态变量存储请求、连接、用户临时数据**

    - 协程场景必须使用协程上下文存储临时数据

3. **禁止阻塞事件循环**

    - 业务代码严禁使用 `sleep()`、死循环、`exit()`、`die()`

    - 严禁手动 `pcntl_fork()` 创建子进程

    - 耗时计算、阻塞IO、长任务，必须拆分独立 Worker 进程或投递队列，不占用消息处理进程

4. **异常容错保进程**

    - 所有事件回调（onMessage/onConnect/onClose/定时器）必须包裹 try\-catch

    - 禁止异常直接冒泡导致子进程崩溃退出

    - 捕获异常必须记录堆栈日志，禁止静默吞错

5. **资源自动回收与重连**

    - 所有数据库、缓存连接必须自带断线重连，处理 `mysql gone away` 等异常

    - `onClose` 必须清理当前连接绑定的定时器、缓存、临时资源，防止内存泄漏

## 二、代码风格规范（PSR\-12 \+ 框架定制）

统一 AI 输出代码风格，兼顾规范性和框架适配性。

- **基础规范**：严格遵循 PHP PSR\-12 编码标准，命名空间与目录一一对应，统一自动加载

- **类名**：大驼峰（`UserService`），文件名与类名完全一致

- **方法名**：小驼峰（`getUserInfo`）

- **变量/参数**：小驼峰（`$connectionId`）

  两点边界，避免与工具和其他层冲突：

  - 本约定只约束**自有代码**（本地变量、参数、自有属性）。引用第三方属性时保持其原名，
    例：`GatewayWorker\Lib\Context::$client_ip` / `$client_port` 是框架公开属性，
    不得改写成驼峰（phpcs 的 `MemberNotCamelCaps` 无法区分声明与访问，故已排除该码）。
  - **数组键 / 配置键 / Redis Hash 字段名**仍沿用蛇形（`client_id`、`device_id`、
    `archive_enable`）—— 它们是协议与数据格式的一部分，改动即破坏存量兼容，
    与「变量命名」是两件事。phpcs 只检查变量，不检查字符串键。

- **常量**：全大写\+下划线（`MAX_CONN_LIMIT`）

- **回调规范**：Workerman 事件回调仅做分发，业务逻辑抽离独立 Service，禁止大段逻辑嵌套在闭包内

## 三、Workerman 专属禁则（AI 绝对禁止生成）

所有生成代码必须规避以下坑点，出现即视为不合格代码。

1. 禁止在主进程初始化 DB、Redis、MQ 等网络连接

2. 禁止业务代码出现 `exit/die/sleep/pcntl_fork`

3. 禁止全局/静态变量存储连接实例、请求上下文、临时业务数据

4. 禁止 onMessage 内写无退出条件的死循环

5. 禁止定时器全局随意注册，仅可在 onWorkerStart/onConnect 内注册

6. 禁止跨进程依赖定时器 ID、全局状态数据

7. 禁止阻塞事件循环，所有回调逻辑轻量化、快速返回

## 四、Workerman 专属强制规范（AI 必须实现）

1. **进程配置规范**

    - CPU 密集型任务：进程数 = CPU 核心数

    - IO 密集型任务：进程数 = CPU 核心数 3\~8 倍

    - Windows 环境强制单进程，不配置 count 多进程

2. **定时器规范**

    - 定时器统一在 onWorkerStart 注册

    - 连接专属定时器，onClose 必须手动销毁，防止残留定时器内存泄漏

3. **连接处理规范**

    - 禁止全局保存 $connection 对象

    - 消息处理必须做参数校验、长度限制，大消息分片处理，避免内存暴涨

4. **重启规范**

    - 业务代码变更使用 reload 平滑重启（仅重启子进程）

    - 主进程配置、初始化代码变更必须 full restart

## 五、协程场景补充规范（Webman/Workerman 协程）

1. 禁止多协程共用同一个 DB/Redis 连接实例，必须使用连接池

2. 禁止请求数据存入静态/全局变量，统一使用协程上下文

3. 并发临界区资源竞争，必须使用 Workerman\\Locker 加锁保护

4. 协程任务必须捕获异常，避免单个协程异常影响整个进程

## 六、日志与异常监控规范

1. 所有事件回调、定时器、异步任务必须包裹 try\-catch

2. 日志必须携带关键参数：worker\_id、connection\_id、请求耗时、异常堆栈

3. 区分日志类型：启动日志、连接日志、业务日志、异常日志、慢任务日志

4. 核心埋点：连接数、消息处理量、异常数、定时器漂移、重连次数

## 七、项目目录分层规范（AI 生成项目结构）

```Plain Text
app/
  Services/        # 核心业务服务层，无直接事件依赖
  Processes/       # 独立Worker进程（定时、队列消费、异步任务）
  Protocols/       # 自定义通信协议解析
  Listeners/       # 事件监听、钩子逻辑
  Utils/           # 通用工具类
config/
  worker.php       # 进程配置、监听端口、进程数、全局配置

```

**分层原则**：事件回调只做「接收\-校验\-分发\-返回」，所有业务逻辑下沉至 Service，保证代码可复用、无进程耦合。

## 八、AI 编码自检清单（生成代码必过 5 项校验）

AI 输出代码前必须完成自检，任意一项不通过则重写代码：

1. 是否存在主进程初始化网络连接？

2. 是否存在 exit/die/sleep/手动 fork 阻塞代码？

3. 是否用全局/静态变量存储临时请求/连接状态？

4. 所有回调、异步任务是否完整 try\-catch 容错？

5. 是否存在阻塞事件循环、未回收资源的逻辑？

## 十、Gateway\-Worker 分布式架构专属补充规范

适用于 **Gateway\-Worker 集群架构**（Gateway 网关进程 \+ BusinessWorker 业务进程分布式分离模式），为架构专属强制编码规则，优先级等同于核心基础原则，AI 生成集群代码必须严格遵守，杜绝分布式数据错乱、推送失败、离线数据丢失、进程耦合等集群专属问题。

### 10\.1 核心架构认知（AI 编码基础）

Gateway\-Worker 采用**网关与业务分离**分布式架构，两类进程职责完全隔离，禁止跨职责混用能力：

- **Gateway 进程**：只负责连接接收、协议解析、心跳维护、消息转发、客户端连接管理，**不处理任何业务逻辑、不连接数据库/Redis/MQ**

- **BusinessWorker 进程**：只负责接收 Gateway 转发的消息、执行业务逻辑、数据读写、消息推送，**不直接监听客户端连接**

- **Register 进程**：仅做节点注册、心跳发现、集群调度，业务代码禁止读写、干预 Register 逻辑

### 10\.2 分布式强制禁则（AI 绝对禁止）

以下为集群致命坑点，禁止生成任何违规代码：

1. **禁止在 Gateway 进程执行业务操作**：禁止 Gateway 中初始化 DB/Redis、查询业务数据、处理业务判断、执行推送逻辑

2. **禁止 BusinessWorker 直接操作客户端连接**：不直接监听端口、不直接调用原生连接发送方法，所有客户端消息推送必须通过 `Gateway::sendToClient/sendToGroup` 官方方法

3. **禁止依靠本地进程内存存集群状态**：单节点内存变量无法跨进程、跨节点共享，禁止用全局/静态变量存储用户在线状态、分组信息、会话数据

4. **禁止随意修改 Gateway 协议与转发逻辑**：禁止拦截、篡改 Gateway 原始转发报文，避免集群消息丢失、粘包分包异常

5. **禁止在 Gateway 中注册定时器执行业务**：心跳、超时、业务定时逻辑统一放在 BusinessWorker，Gateway 仅保留基础连接维护能力

6. **禁止跨进程硬编码节点 ID、端口**：集群节点配置统一读配置文件，禁止硬编码集群地址，保证集群扩容无感知

### 10\.3 Gateway\-Worker 专属强制编码规则

1. **客户端 ID 唯一标识规范**所有客户端操作、推送、分组、离线绑定，统一使用框架原生 `$client_id` 作为唯一标识

2. 禁止自定义连接 ID 替代原生 `client_id`，避免集群节点识别异常

3. 用户登录后必须执行 `Gateway::bindUid($client_id, $uid)`，解绑/退出执行 `Gateway::unbindUid`

4. **分组与广播规范**用户分组统一使用 `Gateway::joinGroup/leaveGroup`，禁止自行维护分组列表

5. 全员广播、分组广播、指定用户推送，严格使用对应官方静态方法，禁止循环遍历本地连接推送

6. 批量推送做好异常捕获，规避单客户端异常导致整体推送中断

7. **会话与在线状态存储规范**用户在线状态、会话数据、分组数据**必须存入 Redis 共享存储**，实现全集群节点共享

8. 连接上线/下线事件，必须同步更新 Redis 在线状态、统计数据，保证集群状态一致性

9. **事件回调专属规范**`onConnect`：仅做连接初始化、基础校验，不执行业务登录、数据查询逻辑

10. `onMessage`：统一接收 Gateway 转发报文，参数校验后分发业务逻辑

11. `onClose`：必须同步清理 Redis 在线状态、用户分组、绑定 UID、关联定时器，防止集群脏数据残留

12. **集群重连与容错规范**BusinessWorker 所有网络资源连接支持断线重连，适配集群节点重启、扩容场景

13. 集群节点重启、上下线时，业务无感知，不丢失未推送的合法消息

### 10\.4 分布式全局状态规范（核心避坑）

- 所有**跨节点、跨进程共享数据**（在线用户、分组列表、用户绑定关系、会话缓存）全部下沉 Redis，禁止依赖进程内存

- 本地进程变量仅用于单次消息处理临时缓存，进程重启、节点迁移不影响集群整体状态

- 高频读写的集群状态数据，增加缓存过期与主动刷新机制，避免数据一致性偏差

### 10\.5 Gateway\-Worker 专属 AI 自检项（新增）

集群模式下，AI 代码生成后需额外完成 3 项专项自检：

1. 是否存在 Gateway 进程执行业务、连接数据库等越权逻辑？

2. 集群共享状态是否存入 Redis，是否依赖本地进程内存存储？

3. 消息推送、分组、用户绑定是否使用官方 Gateway 静态方法，无自定义集群转发逻辑？

### 10\.6 集群日志与监控补充

集群架构需额外打印日志字段：**节点类型（Gateway/BusinessWorker）、client\_id、uid、分组 ID、集群节点地址**，快速定位跨节点消息异常、推送失败、状态不一致问题。
